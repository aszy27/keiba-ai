# keiba v2 作り直し計画

2026-09-15 作成。旧システム（`core/`, `train_main.py` ほか）の問題の洗い出しと、それを踏まえた作り直しの設計。
旧システムは「最終テスト2」（CLAUDE.md 参照）の判定に使うため、判定が終わるまで変更しない。

## 決めたこと（2026-09-15）

| 項目 | 決定 | 理由 |
|---|---|---|
| 作業場所 | 同じリポジトリの `v2/` | 旧コードは final2 の判定に必要。データの取得処理は共有する |
| データ形式 | `data/v2/*.parquet`（pyarrow） | 型が保たれる・読み込みが速い・追加の依存なし |
| 券種 | 単勝のみから始める | 確率をそのまま使える。複勝・3連複は単勝で上積みが確認できてから |
| モデル構成 | 基礎モデル（オッズなし）＋オッズ結合の2段階 | オッズの無い2012〜2020年も学習に使え、「オッズに何を足すか」を直接測れる |
| 最適化・評価の指標 | 勝ち馬の対数尤度（オッズのみとの差）と、事前に1つ決めた期待値閾値での回収率 | 的中率ではなく確率の精度と収支で判断する |
| 購入時点オッズ | 締切前のオッズを保存するスクリプトを用意し、取れる週から貯める | 確定オッズでの回収率は実戦より甘い。差の大きさを実測する |

## 旧システムの問題（2026-09-15 時点）

### A. 設計の方向
1. 着順を当てるモデルで、オッズに対する上積みを狙っていない（オッズは学習にも購入判断にも不使用）。
2. Optuna の最適化指標が「上位3頭の3着内カバー率」（`optimize_main.py`）。券種（3連複1点）は列ずれのバックテストで選んだ。
3. 自信度が確率として未校正（`is_unbalance=True`、自信度60%で実的中率14〜16%）。閾値60%はテスト期間を見て決めた。
4. 回収率の検証に確定オッズを使っており、購入時点のオッズより甘い。

### B. 特徴量
5. LightGBM の `FEATURE_COLS` に距離・芝ダ・馬場・競馬場・天候が無い（Transformer 用の列にだけある）。
6. 非重賞の grade「一般」（2025年で約94%）を「OP」に変換しており、新馬〜3勝クラス・OP特別がすべて `grade_score=6`。クラス情報が実質無い。
7. 性別（`gender`）を使っていない。
8. 走破タイム・着差・上がりが距離・馬場・コースで正規化されていない。着順も頭数・クラスを無視。
9. 欠損と0の区別が無い（新馬の前走着順=0、初騎乗の騎手勝率=0、全体を `fillna(0)`）。件数の特徴量も無い。
10. 騎手・調教師成績が2012年からの全期間累積。コース別成績は場×芝ダ×距離の完全一致で疎。
11. 追い切りの欠損を「C」で保存している（`scrape_other_data.py`）。`oikiri_missing` がほぼ機能しない。
12. `popularity` が全期間0のまま `HIST_COLS` に入っている。
13. 取消・除外馬を学習では頭数・先行馬数に数え、本番では除外。
14. Transformer が `horse_id` を埋め込みに使う（学習では丸暗記、テストの新馬は unknown）。
15. DAE の入力8列のうち3列が常に0で、残りは枠・馬番・年齢・斤量・間隔のみ。
16. 血統ベクトル（DeepWalk）は作り直すたびに空間が変わり、モデルの再学習が必要。

### C. 学習
17. DAE特徴量が学習時（分割ごと）と推論時（全データ）で別物。
18. 監督AIは OOF スコアで学習し、推論では最終モデルのスコアを使う。
19. early stopping に使った検証分割でそのまま OOF 予測を作っており、OOF スコアが楽観的。
20. Transformer は3エポック固定で検証・early stopping なし。
21. スケールの違うスコアの加重平均。各モデルの寄与（アブレーション）を測っていない。
22. `best_params.json` 等があると `config.py` が黙って上書き読み込み。Optuna DB は過去の試行と混ざる。
23. 時系列分割がレースID単位で、同じ日が学習と検証に跨りうる。

### D. 評価
24. データ分割がフォルダ（train/val/test）の置き場所で決まり、`scrape_main_data.py` の振り分けと実際の置き場所がずれている。
25. 監督AI用の特徴量作成とスコア合成が train/evaluate/predict/optimize の4か所に別実装。
26. `evaluate_main.py` の回収率に信頼区間が無い。
27. オッズのある期間は検証で使い切り、未使用なのは 2026-09-07 以降のみ。

### E. データ
28. 偽レース・レース情報の欠損・重複行・ID書式ゆれ・払戻の列ずれがあり、取り込み時の検査が無い。
29. 2023年以前は払戻データが一部のレースのみ。
30. 予想時点の状態（出馬表・馬体重・オッズ）を保存していない。

### F. 本番
31. 出馬表の取得失敗時に距離1600m・晴・良を黙って入れる。日付が取れないと今日の日付。
32. 本番のグレード判定（出馬表アイコン）が学習データ（keibascraper）と別経路。
33. 対象レースは `TARGET_IDS` 手書き。馬体重発表前だと全頭が平均体重。

### G. 開発
34. テストが無い。データ・モデルのバージョン管理が無い。実験記録が CLAUDE.md の手書きのみ。

## v2 の構成

```
[段階1] 基礎モデル（オッズを使わない）
   学習: 2012〜2020年 → 出力: 各馬の勝率 p_model
[段階2] オッズとの結合
   log(勝率) = a·log(オッズ由来の勝率) + b·log(p_model) + 残差LightGBM
   学習: 2021〜2025年 → 期待値 = 勝率 × オッズ で単勝を購入
```

## 作る順番と判定

### M1. データ層（問題 24, 28, 29, 30）
- 既存CSVを型付きの表（races / runners / payouts / odds / laps / training / horses）に正規化して parquet に保存。
  - IDは5桁、馬場は「稍」、クラスはレース名から抽出（新馬・未勝利・1勝〜3勝・OP・L・G3〜G1。旧呼称の500万下等も対応）。
  - 着順が無い馬は「取消・除外」と「競走中止等」を区別する。
- 取り込むたびに検査し、エラーがあれば止める: 必須列・型・値の範囲、(race_id, horse_id) 重複、偽レース、
  払戻の整合（3連複 ≤ 3連単）、1着馬のオッズ×100=単勝払戻、レース情報の欠損、1開催日のレース数。
- 分割は日付で指定する（フォルダに依存しない）。
- 締切前オッズのスナップショット取得スクリプト。
- **判定:** 2012〜2026年の全データで検査のエラーが0（警告は内容を確認して記録）。

### M2. 特徴量層（問題 5〜16, 25）
- `build_features(runners, as_of)` 1本を学習・評価・本番で共用。
- リークテスト: 日付Dより後のデータを消しても、D以前のレースの特徴量が変わらないこと。
- 欠損は NaN のまま、件数の列を併記。
- グループ: レース条件 / 能力（スピード指数・上がりの標準化・クラス補正着順）/ 適性（距離帯・芝ダ・場、平均に縮小）/
  近況 / 騎手・調教師（直近1年、縮小）/ 血統（種牡馬×芝ダ・距離帯、縮小）/ 展開（脚質・先行馬数・当日バイアス）/ 追い切り。
- **判定:** リークテストが通る。

### M3. 基礎モデル（問題 17〜23）
- LightGBM（レース内ソフトマックス）1本。walk-forward: 学習 2012〜2018 / early stopping 2019 / 評価 2020。
- 特徴量グループのアブレーション。
- **判定:** 同じ期間で旧モデルより勝ち馬の対数尤度が良い。

### M4. オッズ結合（開発）
- 学習 2021-01〜2023-12 / early stopping 2024 / 報告 2025。
- 候補1つと期待値閾値1つをここで決める。確定オッズを割り引いた回収率も併記（割引率はスナップショットとの差から決める）。

### M5. 最終テスト（事前登録）
- 期間: 2026-09-07 以降（final2 と同じ。結果を見ていない唯一の期間）。final2 を実行する前に候補を固定して CLAUDE.md に登録する。
- 同じ期間で2候補を判定するため区間は97.5%を使う。
- 合格: オッズのみとの対数尤度差の97.5%区間が0を含まない、かつ事前に決めた閾値で回収率100%超。不合格なら本番化しない。

### M6. 本番（合格時のみ）
- 締切前にオッズを取り、予測・買い目出力。賭けた記録を自動保存し、実戦とバックテストの差を毎週確認。

## 進捗

### M1 データ層（2026-09-15 実装）
- `python -m v2.ingest`: 旧CSV → `data/v2/{races,runners,payouts,odds_final,laps,training,horses,courses}.parquet`。
  検査結果は `data/v2/check_report.txt`、元ファイルのサイズ・更新日時は `data/v2/manifest.json`。ERROR があれば保存しない。
- `python -m v2.fetch_patches`: 検査で見つかった穴を netkeiba から取り直し `data/v2/patches/` に保存（旧CSVは書き換えない）。
  実施結果: レース情報の欠損88R（=文字化けしたレース名の88Rと同一）を補完、2014-04-13 阪神の抜け10Rを取得。
- `python -m v2.scrape_odds_snapshot`: 開催日に起動すると発走30・10・3分前のオッズを `data/v2/odds_snapshots/` に保存。
  過去日（9/13）でレース一覧とAPIの応答を確認済み。開催中の応答（status）は次の開催日に確認する。
- 正規化で入れたもの: 文字化けしたレース名の復元（EUC-JPを1バイト文字コードで読んだ化け。候補の文字コードのうちレース名の語が最も多く出るものを採用）、
  クラス（新馬〜G1。旧呼称500万下等も対応。読めない5Rは同年の1着賞金から推定）、ID5桁、出走状態（finished / dnf=通過順あり / scratched）。
- **判定: ERROR 0件で通過。** 確認済みの WARN:
  - 1開催日のレース数が11未満: 2019-05-04 東京9R、2026-02-07 東京7R。netkeiba のレース一覧でも同数で、欠けではない。
  - 馬連 > 馬単 42R（0.18%）: 別々の投票プールなので起こりうる。
  - 2024年以降で払戻の無い72R・血統マスタに無い106頭: 2026-09-05/06 開催分の未取得。毎週の取得で解消する。
  - 平地の上がり3F・走破タイムの範囲外（INFO）: 大差の最下位など実在の記録。特徴量側で丸める。
  - 障害レースの last_3f は平地と単位が違うため空にしている。追い切りの「C」には旧スクレイパーの「評価なし」が混ざる（直せない）。

### M2 特徴量層（2026-09-15 実装）
- `v2/features.py` の `build_features` 1本（95特徴量、全期間70万頭で約30秒）。`python -m v2.features` で `data/v2/features.parquet`。
- 過去成績は「日ごとの累積」から race_date より前の最後の値を `merge_asof` で取るため、同日・未来の結果は構造上入らない。
- リークテスト（`v2/tests/test_features.py`）: 未来のレースを消しても・当日の結果を消しても特徴量が変わらないことを確認済み。
- スピード指数 `fig` = その日より前の同条件（場・芝ダ・距離・馬場、件数が少なければ粗く）の勝ち時計平均との差（秒/1000m、±15で丸める）。

### M3 基礎モデル（2026-09-15 実施、`python -m v2.model_base --ablation`、ログ `model_base_v2.log`）
- LightGBM（レース内ソフトマックス）。学習 2013〜2018 / early stopping 2019 / 評価 2020（3,447R）。2019年で温度を合わせて評価。
- 2020年の1レースあたり対数尤度: **v2 -2.1077** / 全馬同じ確率 -2.6097。
- **判定: 通過。** 旧モデル（OOFスコア: LGB2種+Transformer を条件付きロジットで結合）-2.1513 に対し、差 **+0.0437 [95%区間 +0.0295, +0.0585]**。
  旧モデルの OOF は early stopping に使った期間をそのまま予測している（問題19）ので旧モデルに有利な比較。
- 較正: 予測勝率0.5未満の帯は実際の勝率とほぼ一致。0.5以上（232頭）は予測0.58に対し実際0.45でやや過大。
- 重要度上位: 直近3走の着順の相対位置（レース内比較）、前走着順、追い切り、騎手・馬の複勝率（レース内比較）、スピード指数。
- アブレーション（外したモデル − 全部入り）: レース条件 -0.026 [-0.035, -0.017] / 馬の過去走 -0.026 [-0.036, -0.016] /
  成績の集計 -0.006 [-0.014, +0.002] / レース内の比較 +0.002 [-0.005, +0.010]。
  後の2つは単独では区間が0を含む（互いに同じ情報を持つため、片方を外してももう片方で補える）。今は全部入りのまま進める。

### M5 最終テスト（事前登録: 2026-09-15。判定まで変えないこと）
- **登録し直し（2026-09-15）:** 最初は 2026-09-07 以降が1,000Rたまるのを待つ登録だったが、今あるデータだけで判定したいという方針により、
  期間を **2026-01-01〜2026-09-06** に変更した。v2 はこの期間の成績を一度も計算・表示していない時点での変更で、候補・閾値・合格条件は変えていない。
  - 限界: この期間は旧システムの調査（CLAUDE.md の0〜4章）で成績を見ており、v2 の特徴量の設計がその知見に影響されている可能性はゼロではない。
- **候補: C（オッズ + 基礎モデルの条件付きロジットを出発点に、残差を LightGBM で学習）。閾値: 期待値 1.1 以上の単勝。**
  - 閾値 1.1 を選んだ理由: 開発の2年（2024・2025）の両方で100%を超え、点数も870点ある。1.2 は点数が少なく区間が広すぎる。
    ただしこの選択は 2024・2025 の結果を見て行ったもので、M5 はその選択が別の期間でも通用するかを確かめる。
- 設定（`v2/model_combined.py` の `FINAL_SPLIT` ほか）: 学習 2022〜2024 / early stopping 2025 / 報告 2026-01-01〜2026-09-06（約2,440R）。
  開発（`--year`）と同じ配置。基礎モデルの2026年分の予測は 〜2024年で学習・2025年で early stopping（`base_oos.parquet` 作成済み）。
  区間は最初の登録どおり97.5%（条件を緩めない）。
- 手順: `python -m v2.model_combined --final` を**1回だけ**実行し、結果をこの節に記録する。
- **結果（2026-09-15、登録のコミット 76be25a の後に1回実行、2,440R、ログ `model_combined_final.log`）: 不合格。**
  - 対数尤度: A オッズのみ -1.9292 / B オッズ+基礎モデル -1.9291 / C -1.9255。
  - C − A: **+0.0037 [97.5%区間 -0.0009, +0.0080]**（0を含む）。B − A: +0.0001 [-0.0001, +0.0003]。
  - 期待値1.1以上の単勝（C、確定オッズ）: **48点・的中4・回収率45.8%** [5, 84]。オッズのみ（A）は10点で120%（点数が少なく参考にならない）。
  - 開発（2024・2025）では1.1以上が年に数百点あったのに対し、この期間は48点しかない。モデルがオッズから離れる馬が少なく、離れた馬も当たっていない。
- 結論: 旧システムと同じく、オッズに対する上積みは +0.002〜0.008 程度で年によって出たり出なかったりし、回収率100%超えにはつながらない。
  v2 でデータ・特徴量・学習の問題を直し、着順予測は旧モデルより明確に良くなった（M3）が、市場に勝つには至らなかった。
  **この期間（2026-01-01〜2026-09-06）は M5 で使い切った。** 同じ期間で候補を差し替えて試さない。
- **合格の条件（両方）:** オッズのみ（A）との対数尤度の差の97.5%区間の下限が0より大きい、かつ期待値1.1以上の単勝の回収率（確定オッズ）が100%超。
  締切前オッズのスナップショットが取れていれば、その差も参考として報告する（判定には使わない）。
- 不合格なら本番化しない。合格しても、まずスナップショットのオッズで回収率を確認してから少額で始める。

### 券種間の値付けのずれ（2026-09-15 開始。開発の結果を見る前に記録）
- 仮説: 単勝オッズから計算した組み合わせの確率（ハービル式）に比べて、馬連・馬単・3連複・3連単の払戻が
  特定の組み合わせ（とくに荒れる組み合わせ）で割安・割高になっていないか。馬の強さではなく投票プール間の歪みを突く。
- データ: 確定単勝オッズ・着順・払戻（今あるデータのみ）。コードは `v2/exotic_edge.py`。
- 期間: **開発 2021〜2023年**（払戻があるのは一部のレース）/ **最終テスト 2024〜2025年**（この仮説では未使用）。2026年は M5 で使い切ったので使わない。
- 手順: 開発期間だけを見て、試すルール（券種 + 買う組み合わせの条件）を**1つだけ**決めてここに登録 → `--period test --final` を1回だけ実行。
- **合格の条件: 回収率の95%区間（レース単位のブートストラップ）の下限が100%を超える。**
  高配当の券種はばらつきが大きく、点推定が100%を超えるだけでは偶然と区別できないため。
- 限界: 確定オッズを使うので実戦より甘い。ハービル式は2・3着の確率の偏りが知られており、ずれがあってもそれが原因の可能性がある。
- **開発期間の結果（2026-09-15、払戻のある3,769R、ログ `exotic_edge_dev.log`）: 登録できるルールなし → 最終テストは実行しない。**
  - 馬連・馬単・3連複・3連単のどの確率帯・荒れ度合いでも、回収率の点推定は100%未満（最高 3連複の確率0.03〜0.1 で83.1%）。
    95%区間の上限が100%を超えたのは、3連単の確率0.1以上（187点・71.8% [40, 107]）だけ。
  - 荒れる組み合わせほど回収率が低い: 一番人気の低い馬が13〜18番人気の組み合わせは、どの券種も約47%。10〜12番人気でも55〜64%。
    人気馬だけの組み合わせは75〜81%で、ほぼ控除率どおり。
  - 低い確率の組み合わせは、ハービル式の見込みより多く当たっている（3連複の確率0.0001〜0.0003: 見込み42回 → 実際108回）。
    それでも回収率は68%で、払戻が見込み以上に安い。**単勝と同じく、組み合わせの投票でも穴は買われすぎている。**
- 結論: 荒れる組み合わせが割安に放置されている形跡はなく、逆に割高。券種を変えても、オッズだけから作るルールで控除率を超える余地は見えない。

### 当てやすいレースの選択（2026-09-16 開始。開発の結果を見る前に記録）
- 仮説: 人気どころを当てるだけでも、1番人気がオッズの見込み以上に勝つ条件のレースだけを選べば、単勝がプラスになる。
- 買い方: 1番人気（確定単勝オッズが最も低い馬。同値のレースは除く）の単勝を1点。コードは `v2/favorite_segments.py`。
- 条件の候補（1軸ずつ、約40通り）: 頭数 / クラス / 芝ダ / 距離 / 馬場 / 競馬場 / 1番人気のオッズ / 1番人気と2番人気のオッズ比。
- 期間: **開発 2021〜2023年 / 最終テスト 2024〜2025年**。
  - 限界: 2024〜2025年は v2 の M4（オッズ＋残差モデルの単勝）で結果を見ている。この仮説（1番人気のレース選択）では未使用。
- 条件の選び方（機械的に決める）: 開発期間で300R以上ある条件のうち、回収率の95%区間（レース単位のブートストラップ）の下限が最も高いもの1つ。
- **合格の条件: 最終テスト期間で、選んだ条件の回収率の95%区間の下限が100%を超える。**
- **開発期間の結果（2026-09-16、1番人気が単独の10,154R、ログ `favorite_segments_dev.log`）:**
  - 全レース: 的中率33.5%・回収率80.0% [77.5, 82.4]。約40の条件のどれでも点推定は100%未満（最高は京都 90.2% [76.8, 104.1] の342R）。
  - クラス別: 2勝 86.6% / 1勝 83.5% / 未勝利 78.3% / 3勝 70.7% / OP・L 71.1% / 重賞 68.5%。
  - 1番人気のオッズ別: 〜1.5倍 87.8% / 1.6〜2.0倍 79.2% / 2.1〜3.0倍 79.7% / 3.1〜5.0倍 79.6%。
  - **選ばれた条件（登録どおり機械的に選択）: 1番人気のオッズ=〜1.5倍（722R・的中率63.6%・回収率87.8% [82.8, 92.7]）。**
    開発期間でも区間の上限が100%に届いていないが、手順どおり最終テストを1回行う。
- **最終テストの結果（2026-09-16、登録のコミット cd93169 の後に1回実行、ログ `favorite_segments_final.log`）: 不合格。**
  - 1番人気のオッズ〜1.5倍: 538R・的中率61.7%・平均オッズ1.37倍・**回収率83.2% [77.5, 88.6]**。
  - 同期間の全レース（6,647R）: 的中率34.0%・回収率79.0% [76.4, 81.9]。
- 結論: 1番人気が固いレースほど的中率は上がる（34% → 62%）が、オッズも下がるため回収率は控除率（約80%）の近くにとどまる。
  開発期間の約40条件でも点推定が100%を超えるものは無く、「当てやすいレースを選ぶ」だけで控除率を超える余地は見えない。

### 地方競馬（2026-09-15 開始）
- データ: netkeiba 地方版の結果ページ（1レース1リクエストで 着順・馬番・騎手・タイム・人気・確定単勝オッズ・全券種の払戻と組み合わせ がそろう）。
  地方版のオッズAPIは中身が空のため使わない。ばんえい（帯広）は除く。
  - `python -m v2.nar.fetch_results --start ... --end ...` → `data/nar/raw/*.html.gz`（HTMLをそのまま保存、再実行で続きから）
  - `python -m v2.nar.parse_results` → `data/nar/{races,runners,payouts}.parquet`
  - `python -m v2.nar.market_check` → 単勝市場の歪みを同じ期間の中央と比べる
- **段階1（2026年6〜8月、約3,500R）で続けるかを決める。基準（3か月分の結果を見る前に記録）:**
  - 続ける: 次のどちらか
    1. 人気帯またはオッズ帯のどれかで、単勝回収率の95%区間の下限が100%を超える（単純なルールで控除率を超える歪みがある）
    2. オッズの勝率を alpha で直したときの対数尤度の改善が、期間の後半で95%区間の下限 > 0 で、かつ中央（同じ期間）より大きい
       （オッズの確率が一律にずれていて、モデルで直せる余地が中央より大きい）
  - どちらも満たさなければ止める（中央と同じ程度に効率的とみなす）。
  - 注意: 回収率の区間は馬単位のブートストラップで、同じレース内の相関を無視しているため実際より狭い。
    1 を満たした場合も、段階2でレース単位の検証をやり直す。
- **段階1の結果（2026-09-15、2026年6〜8月の3,537R・13場、ログ `nar_market_check.log`）: 基準をどちらも満たさず → 止める。**
  - 実質の払戻率 0.786（中央 0.791）。1レース平均10.0頭（中央13.2頭）。取得3,562R、パース失敗0件。
  - 基準1: どの人気帯・オッズ帯でも回収率の95%区間の下限は100%未満。区間の上限でも最大92.6%（オッズ20〜50倍）。
    人気帯別の回収率: 1番人気 78.7% / 2番人気 80.8% / 3番人気 71.1% / 4〜5番人気 75.5% / 6〜8番人気 60.2% / 9〜12番人気 57.0%。
    オッズ帯別では2〜50倍が76〜80%でほぼ控除率どおり、50倍以上は25〜57%（中央と同じく大穴は買われすぎ）。
  - 基準2: alpha = 1.048（中央 1.059）。後半での補正の改善 +0.0007 [-0.0014, +0.0028]（中央 +0.0015 [-0.0030, +0.0060]）。
  - 結論: 地方の単勝市場も、オッズから見た勝率と実際の勝率がほぼ一致しており、中央と同じ程度に効率的。
    単純なルールやオッズの補正で控除率を超える歪みは見えない。
  - 限界: 段階1が調べたのは「オッズの値付けの偏り」だけで、特徴量を使ったモデルがオッズ以上の情報を持てるか（v2 の M4 に当たる検証）は
    地方ではしていない。ただし中央でそれが届かなかったこと、地方も値付けが同程度に正確なことから、見込みは低いと判断した。

### 特徴量の追加を打ち切る基準（事前登録: 2026-09-17。第5弾を作る前に記録）
「精度が上がらなくなるまで特徴量を増やす」作業の終了条件を、結果を見る前に決めておく。
- 各弾で測る2つの指標（どちらも開発期間だけ。最終テストの期間・2026-09-07以降は触らない）:
  1. **オッズ抜きの当てやすさ**: `v2/feature_lab.py`（学習 2013〜2017 / ES 2018 / 報告 2019〜2020）の「全部入り」の対数尤度。
     **前の弾の全部入りを基準にした差**（95%区間つき）で測る。そのため `--wave N` を追加し、基準を前弾の全部入りに変えられるようにする。
  2. **オッズへの上積み**: `v2/model_trip.py --sets all` の C[all] − A（開発 報告2019年・2020年）の平均。
- **打ち切り条件**: 1の前弾比の伸びが **+0.003 未満**、かつ 2の前弾比の伸びが **+0.002 未満** の弾が **2回続いたら**終了。
  （1弾だけの停滞は、グループの当たり外れで起こりうるため止めない）
- 前向き検証の候補は、終了後に **2（オッズへの上積み）が最大の版**を選ぶ。1が最大の版ではない。
  理由: 第4弾で「オッズ抜きは +0.0049 伸びたのにオッズへの上積みは横ばい」という例が出ており、賭ける判断に効くのは 2 のため。
- 候補を差し替える場合も、2026-09-07以降のデータ（スナップショットは 2026-09-19 から取得開始）は一切見ない。
