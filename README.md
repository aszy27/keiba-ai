# 🏇 Keiba AI Prediction System (3連複 Sniper V8)

LightGBM・Transformer・Denoising AutoEncoder・血統グラフ埋め込みを、完全同期型OOF（Out-of-Fold）パイプラインで
融合させた競馬予測システムです。上位馬のスコア分散やギャップからレースの難易度を判定し、
「上位3頭が揃って馬券内に入る確率」を出す監督AI（メタモデル）を備えています。

**学習（train_main）・バックテスト（evaluate_main）・本番予測（predict_main）の3経路で、特徴量が同一条件になるよう設計**し、
train/serving skew（学習時と推論時の分布ズレ）を継続的に潰しています。

> **現在の到達点**: 着順予測（3着内率・勝率）は機能していますが、**回収率では市場を上回れていません。**
> 2026年のテスト期間で3連複1点の回収率は約78%、実戦93レースでも72.8%で、いずれも控除率（25%）並みの水準です。
> 詳細は「実測結果」と「データ品質と検証」を参照してください。

## 📊 実測結果

学習: 2012〜2025年 / テスト: **2026年（学習に一切使用していない期間）** / 1点100円均等投資。

### バックテスト（2026年・自信度60%以上）

| 指標 | 値 |
|---|---|
| 購入レース数 | 436R |
| 3連複的中率 | 16.3% |
| 3連複回収率 | **78.2%** |
| 的中時の平均払戻 | 約480円 |

### 実戦（2026/7/18〜9/6・自信度60%以上）

| 指標 | 値 |
|---|---|
| 購入レース数 | 93R |
| 的中 | 13R（14.0%） |
| 回収率 | **72.8%** |
| 的中時の平均払戻 | 521円 |

バックテストと実戦の的中率・回収率・平均払戻がいずれも一致しており、
**学習時と推論時で条件がズレていない（train/serving skew がない）ことは確認できています。**
一方で、**3連複で市場に勝てている形跡はありません。** 単勝回収率72〜80%・複勝回収率82〜90%も
どの自信度の閾値でも100%を超えず、モデルの評価は市場（人気）とほぼ同じであることを示しています。

自信度は「3頭完全的中率」という名前ですが確率としては未校正で、自信度60%のレースの実際の的中率は14〜16%です
（`is_unbalance=True` で学習しているため値が大きく出ます）。閾値は順位付けの指標として使っています。

### 券種ごとの実測
`evaluate_tickets.py` で、単勝・複勝・馬連・馬単・ワイド・枠連・3連複・3連単の回収率を
自信度の閾値ごとに測定できます（結果は `result/ticket_roi.csv`）。AIの上位馬から各券種を1点（ワイド3点は上位3頭の総当たり）買った場合の、2026年テスト期間の回収率です。

| 券種 | 全レース (2370R) | 自信度60%以上 (436R) | 自信度70%以上 (162R) |
|---|---|---|---|
| 単勝 | 71.0% | 73.0% | 74.2% |
| 複勝 | 79.1% | 85.2% | 83.9% |
| 馬連 | 70.7% | 74.4% | 90.2% |
| 馬単 | 55.1% | 71.7% | 92.1% |
| 枠連 | 70.9% | 60.1% | 53.3% |
| ワイド1点 | 74.8% | 75.0% | 81.6% |
| ワイド3点 | 78.4% | 83.2% | 94.9% |
| 3連複 | 74.3% | 78.2% | 92.3% |
| 3連単 | 44.7% | 61.7% | 92.2% |

どの券種・閾値でも100%に届いていません。自信度を上げると回収率が上がる券種もありますが、70%以上は162Rしかなく、
優位性があるとは判断できません。

## 🔍 データ品質と検証

このプロジェクトで一番時間をかけたのは、モデルの改良ではなく**「測定値が正しいかどうかの検証」**です。
実戦の成績がバックテストに届かない原因を調べる過程で、以下のデータ不具合を発見・修正しました。

### 1. 払戻データの列ずれ（回収率の過大評価）
`data/return_data_progress.csv` のヘッダは `tansho, fukusho, umaren, ...` の順なのに、
実際の行の約91%（21,666/23,893行）はスクレイパー側の `RETURN_COLS`（枠連が3列目）の順で書かれていました。
このため列名で「3連複払戻」を読むと、実際には**馬単の払戻**が入っていました。

* 検出方法: 「馬単 < 馬連」が16,427行、「3連複 > 3連単」が8,211行。いずれも配当の仕組み上ありえない。
* 列順をそろえ直すと、前者は68行（同着絡み）、後者は0行になり、netkeibaの結果ページとも一致。
* 影響: **「自信度75%以上で回収率176.8%」という以前の記載はこの不具合によるもので、撤回しました。**
  正しい払戻で測り直すと、同条件の回収率は80%前後です。
* 単勝・複勝は列位置が変わらないため元から正しく、学習は払戻データを使わないためモデル自体への影響はありません。

### 2. 「偽レース」の混入
keibascraper が、あるレースIDに対して**同じ開催日の別レースの出走馬・着順**を返すことがありました（2026年で6レース）。
同じ馬が1日に6回走った記録になり、前走成績・出走間隔が壊れます。
同じ日に出走馬の組み合わせが完全一致するレースを検出して除外し、`rescrape_races.py` で取り直します。

### 3. レース情報の欠損
2026年8月以降の中京・9月の全レースなど181レースで、芝ダ・距離・天候・馬場が空欄でした。
コース特徴量やコース別成績に直接効くため、`repair_race_info.py` で結果ページから補完しています。

### 4. 騎手・調教師IDの書式ゆれ
race_data は2014〜2025年が `1170`、2012〜2013年と2026年が `01170` と年によって書式が異なり、
出馬表側は常に5桁でした。このため2026年の騎手成績が2026年分だけで計算され（騎乗履歴の中央値が4,873件→326件）、
同じ騎手でも「乗り替わり」と判定されていました。`core/features.py` で5桁に統一しています。

### 検証ツール
* `evaluate_dump.py` — レース単位のバックテスト結果を保存し、①高配当への依存度 ②少数レースでの回収率のばらつき（ブートストラップ）
  ③本番予測とバックテストの買い目一致率（train/serving skew の検出）を診断します。
* `predict_main.py` の鮮度チェック — 前週の結果が未取得、血統・生産者マスタに未登録の馬がいる、
  レース情報が欠損している、馬体重が未発表、といった「学習時と条件がズレる状態」を実行前に警告します。

### 既知の課題（未対応）
* **DAE特徴量が学習時と推論時で別物** — LightGBMが学習した `dae_*` はFoldごとに別々に学習したDAEの出力ですが、
  推論では全データで学習し直した別のDAEを使うため、潜在空間が対応していません（特徴量としての寄与は約3%）。
* **監督AIのスタッキングのズレ** — 監督AIはFoldモデルのOOFスコアで学習し、推論では最終モデルのスコアを受け取るため、
  自信度の分布がずれます。自信度が確率として未校正な一因です。
* **取消・除外馬の扱い** — 学習では出走扱い（頭数・レース内の先行馬数・LambdaRankのグループに含まれる）ですが、
  本番の出馬表では除外されます。全レースの約10%に該当します。
* **馬体重の発表前に予想すると全頭が平均値になる** — 学習時は全馬に実測値があります。鮮度チェックで警告します。

## 🧠 システムアーキテクチャ

本予測システムは、以下の5つの独立したモジュール表現をブレンドして最終スコアを算出します。

1. **LightGBM LambdaRank (`ranker`)** レース内での着順（相対順位）の最適化に特化したランキング学習モデル。3連複を射止めるために `NDCG@3` を最大化するようにチューニングされています。V8では1着〜4着を**5段階の個別配点（`label_gain=[0, 10, 30, 100, 200]`）**で学習し、単なる「3着以内か否か」より精密に着順を学習します。
2. **LightGBM Classifier (`clf`)** 対象の馬が3着以内（馬券内）に入線するかどうかの絶対確率を予測する二値分類モデル。不均衡データ（`is_unbalance=True`）に対応。
3. **RacingTransformer (`transformer`)** PyTorchで実装された時系列シーケンスモデル。馬の過去5走の成績動向（着順、タイム差、上がり3F、ペース等）をアテンション機構で解析し、現在の潜在能力を評価します。デビュー馬向けの専用埋め込み（`debut_embedding`）も内蔵。
4. **StrongDAE (`dae`)** Denoising AutoEncoder（ノイズ除去自己符号化器）。基本特徴量にガウシアンノイズを注入して学習させることで、データのブレや欠損に強い32次元の頑健な潜在表現（エンベディング）を抽出します。
5. **Graph Embedding / DeepWalk (`p_vec`)** NetworkXを用いて数万頭の血統マスタから家系図ネットワーク（無向グラフ）を動的に構築。ランダムウォーク（Walk=30, N=10）とWord2Vec（skip-gram）により、血統の相関関係を64次元のベクトル空間に埋め込みます。

最終的に、これら5モデルのスコア（1着〜4着スコアのギャップ・標準偏差・平均等）を「監督AI（メタモデル）」に入力し、レースごとの3頭完全的中確率（自信度）を算出します。

## 🔧 V8 での主な強化ポイント

* **学習・バックテスト・本番の完全整合** `core/features.py` に特徴量エンジニアリングを一元化し、`rank`（欠損時の統一値）・`condition`（「稍重」→「稍」表記統一）・`grade`（「一般」→「OP」統一）・`oikiri_rank`（追い切り評価の欠損判定）を3経路すべてで同一ロジックに統一しました。
* **日付排他型の累積成績集計** 騎手・調教師・生産者の勝率／複勝率を「そのレース当日を含む同日の他レース結果」が混入しないよう、**日付単位で厳密に「当日より前」のみ**を集計するように修正（旧実装は同日の先行レース結果が学習時のみ混入するリークがありました）。
* **モデル/特徴量バージョンの不整合検知** `core/inference.py` がTransformer・LightGBMの入力次元・特徴量数を起動時にチェックし、`core/config.py` の `FEATURE_COLS`/`NUM_COLS` 変更後に古いモデルを誤ってロードした場合は明示的にエラー停止します。`optimize_main.py` もOOFキャッシュのバージョンタグ（`__cache_version__`）を検証します。
* **監督AIの入力強化** 1着〜4着のスコアとギャップ（`score_3rd`, `gap_1_2`, `gap_3_4` 等）をメタモデルの入力に追加し、レース難易度の判定精度を向上。
* **本番予測に購入閾値ガードを追加** `predict_main.py` の `BET_THRESHOLD`（デフォルト60%）を境に、レポート上で「〇 購入対象」「⚠️ 見送り推奨」を明示。斤量スクレイピングのバグ修正（斤量が常に55.0固定になっていた不具合）や、生産者データ・追い切り評価の本番/学習間の不整合も解消しました。
* **月別ROI推移（コンセプトドリフト）チェック** `evaluate_main.py` に、学習データの終端からの経過月数に応じて回収率が劣化していないかを可視化する診断セクションを追加しました。

## 🛠️ 実行手順・パイプラインの流れ

システムを利用する際は、必ず以下の **【STEP 1】から【STEP 5】の順番** でスクリプトを実行してください。

### 【STEP 1】環境構築
Python 3.8以上がインストールされている環境で、ターミナルから必要な外部依存ライブラリを一括インストールします。

```bash
pip install -r requirements.txt
```

### 【STEP 2】データの収集とマスタデータの作成
AIの学習ソースとなるレースデータ、およびコースと血統のマスタを構築します。

1. **コースマスタの生成**
   ```bash
   python create_course_master.py
   ```
   * 実行すると、JRA全10場の「直線距離」「高低差」「急坂の有無」を定義した `data/master_course_data.csv` が自動生成されます。

2. **ベースレースデータの取得**
   `scrape/scrape_main_data.py` を開き、設定エリアの `TARGET_YEAR` に取得したい年（例: `2023` や `2026` など）を指定して実行します。
   ```bash
   python scrape/scrape_main_data.py
   ```
   * 指定した年数に応じて、自動的に `data/train/`、`data/val/`、`data/test/` へフォルダが振り分けられ保存されます。

3. **血統情報の取得**
   ```bash
   python scrape/scrape_horse_ped.py
   ```
   * 収集した全レースデータから登場するすべてのユニークな馬IDを自動抽出し、ネット競馬データベースから「父」「母」のIDを巡回取得して `data/master_horse_data.csv` を作成・追記します。

4. **拡張データ（ラップ・追い切り・払戻金）の取得**
   ```bash
   python scrape/scrape_other_data.py
   ```
   * 存在するすべての `race_data_*.csv` を全自動でスキャンし、まだ取得していない「ラップタイム」「当日の追い切り評価」「レースの払戻金」を差分検知してステルスモードで自動収集・同期します。

5. **データの不具合チェック**
   ```bash
   python repair_race_info.py --dry-run
   ```
   * レース情報（芝ダ・距離・天候・馬場）の欠損や、別レースのコピーになっている「偽レース」を検出します。見つかった場合は `--dry-run` を外して補完・削除します（詳細は「データ品質と検証」）。

### 【STEP 3】血統エンベディングの学習 (DeepWalk)
家系図のネットワーク構造を数値化します。

```bash
python train_graph_embedding.py
```
* `data/master_horse_data.csv` から親子関係のエッジを張り、Word2Vecによるスキップグラム学習を実施します。
* **特徴:** 環境に依存しない不変ハッシュ関数（MD5ベース）を内蔵しているため、別PCでいつ実行しても完全に同じベクトル空間が再現され、`data/horse_vectors.csv` に保存されます。

### 【STEP 4】モデルのメイン学習 (OOF同期パイプライン)
時系列データリークを極限まで遮断した、同期型のメイン学習を行います。

```bash
python train_main.py
```
* **処理の流れ:** TimeSeriesSplit（5分割）によるループが起動します。
* ループ内で、そのFoldの訓練データだけを用いて PyTorchの `RacingTransformer` と `StrongDAE` を学習 ➔ 検証データ（Val）に対して推論特徴量を生成 ➔ そのDL特徴量を結合した上で、LightGBM（Ranker / Classifier）の学習を行います。
* 全Fold終了後、未来情報の混入がゼロのクリーンな状態の `data/oof_features_cache.pkl`（OOFキャッシュ）が生成され、最後に全データをフラットフィッティングした本番用最終モデル重みが `models/` に保存されます。

### 【STEP 5】ハイパーパラメータの全自動最適化 (Optuna)
OOFキャッシュ上で「AIの上位3頭がそのまま3着以内に揃う割合（3頭完全的中率）」が最も高くなるようにパラメータを自動チューニングします。
払戻データは使わないため、**回収率を最大化しているわけではありません。**

```bash
python optimize_main.py
```
* **Phase 1**: LambdaRankの評価ターゲットに最適化された、3着以内配点（`label_gain`）の報酬探索。
* **Phase 2**: ランカーモデルのハイパーパラメータ（学習率、葉の数、正則化等）の探索。
* **Phase 3**: 3つのモデルスコア（LGB着順、LGB確率、Transformer確率）の「最強の合成比率（ブレンドウェイト）」の探索。
* **Phase 4**: 監督AI（メタモデル）のパラメータチューニング。
* 最最適化された結果は自動的に `models/best_params.json` 等に保存され、次回の学習や予測に自動適用されます。

## 📈 評価・検証シミュレーションの使い方

モデルの真の実力（回収率・的中率）を、テストデータ（未来のデータ）を用いてシミュレーションします。

```bash
python evaluate_main.py
```
* **カンニング防止機能:** テストデータの予測対象日における未来情報（オッズや最終的な着順、上がりタイム等）をコード内部で自動的に完全に潰して隠蔽した状態で推論を行います。
* **出力結果:** 監督AIが算出した「自信度（3頭完全的中率）」ごとに、各種馬券のリアルな回収率（ROI）テーブルがターミナルに出力されます。

さらに詳しく見る場合:

```bash
python evaluate_dump.py      # レース単位の結果を result/backtest_races.csv に保存し、3つの診断を出力
python evaluate_tickets.py   # 券種別の回収率を result/ticket_roi.csv に保存
```

* `evaluate_dump.py` の診断2（ブートストラップ）は、**少ないレース数では回収率がどれだけブレるか**を示します。
  実戦100レース程度の成績だけでは「モデルが良い／悪い」を判断できないことの確認に使います。
* `evaluate_dump.py` の診断3は、`predict_past/` に残っている本番予想と、同じレースのバックテスト結果を突き合わせます。
  買い目の一致率が低い場合は、本番と学習で特徴量がズレている（train/serving skew）疑いがあります。

## 🔮 当日のレース予測（実戦実行）

競馬新聞や当日の出馬表をもとに、最新の買い目を算出します。

1. `predict_main.py` を開き、最上部付近の設定エリアにある `TARGET_IDS` に、予測したいネット競馬のレースID（開催全体なら10桁、単一レースなら12桁）を指定します。
   ```python
   # predict_main.py
   TARGET_IDS = [
       "202605021211"  # 予測したい当日のレースID（複数指定可能）
   ]
   ```
2. 必要に応じて `BET_THRESHOLD`（実際に賭ける自信度の閾値、デフォルト60%）を調整します。
   * デフォルトの60%は、払戻データの列ずれで過大評価されていたバックテストを根拠に決めた値です。
     正しい払戻で測ると、この閾値でも3連複の回収率は100%を下回ります（「実測結果」参照）。
3. スクリプトを実行します。
   ```bash
   python predict_main.py
   ```

### 📋 予測出力結果の確認
実行が完了すると、`predict/` フォルダに開催・日付ごとのファイルが自動生成されます（例: `1回函館10日目.txt` / 単一レース指定時は `..._11R.txt` のようにレース番号が付与）。

* **`{開催}.txt`** (視認用レポート)  
  監督AIによるレース難易度の診断スタンプ（【超激アツ】3連複1点大勝負！/【勝負レース】/【見送り】など）に加え、`BET_THRESHOLD` に基づく **`〇 購入対象` / `⚠️ 見送り推奨`** の判定が自信度の直後に明示されます。下部には各馬の最終合成スコアとともに `👑 本命`, `✨ 对抗`, `🔺 紐` の印が打たれた、そのまま馬券購入に使えるテキストレポートです。
* **`{開催}_features.csv`** (詳細分析用データ)  
  各馬のディープエンベディング値、特徴量、各モデルが出した生の予測スコアがすべてマージされた詳細なCSVファイルです。
