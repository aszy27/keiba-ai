# 🏇 Keiba AI Prediction System

JRA（中央競馬）のレースで、**AI が「オッズより正しく勝ち馬の確率を見積もれるか」**、そして**それで単勝馬券を買って儲かるか**を確かめているプロジェクトです。

> **今の状況（2026-10-06）**
> - 過去のデータでは「儲かりそう」という結果が出ています。ただしこの数字は甘めに出る条件で測ったものです（理由は「これまでの結果」）。
> - そこで、**本番と同じ条件（実際に馬券を買える発走前のオッズ）で 1,000 レース分を記録し、1回だけ合否を判定**します。判定は 2027年1月ごろの見込みです。
> - **判定が終わるまで、実際のお金は賭けていません。**

---

## まず知っておくとよい言葉

| 言葉 | 意味 |
|---|---|
| オッズ | 当たったときに何倍で返ってくるか。みんなが買う馬ほど低くなるので、「世間がその馬をどれくらい勝つと思っているか」の目安にもなる |
| 控除率 | 馬券の売上から JRA が先に差し引く分（単勝は20%）。そのため、何も考えずに買うと平均で100円が約80円になる |
| 回収率 | 買った金額に対して、戻ってきた払戻の割合。100%を超えれば儲かっている |
| 期待値 | AI の見積もった勝率 × オッズ。たとえば勝率10%と見積もった馬のオッズが13倍なら 0.10 × 13 = 1.3 で、「平均すると 100円が130円になるはず」という意味 |
| 単勝 | 1着になる馬を1頭当てる馬券 |

## 何をしているのか

### なぜ「着順を当てる AI」ではだめなのか
最初に作った AI（旧システム）は、強い馬を当てること自体はできました。しかし、AI が強いと判断した馬は、たいてい世間（オッズ）も強いと見ている人気馬でした。
人気馬はオッズが低いので、当たっても配当が小さく、結局は控除率の分だけ負けます（実際、回収率は約73〜80%でした）。

**儲けるには「当てる」だけでなく、「世間が見落としている馬」を見つける必要があります。**

### 今のやり方
1. **オッズから出発する。** オッズから「世間が見積もった勝率」を計算し、これを基準にします。
2. **オッズが見落としている分だけを AI に学ばせる。** 過去の成績・騎手・血統・コースとの相性・当日の馬場の傾向などから、「オッズの見積もりよりも勝ちやすい／勝ちにくい」分を学習します。
3. **期待値が十分に高い馬だけを買う。** AI の勝率 × オッズが 1.3 以上（100円が平均130円になる見込み）の馬の単勝だけを買います。

この「市場の見積もりを出発点に、ずれだけを直す」考え方は、香港の競馬で成功した研究（Benter, 1994）と同じ形です。

### 一番気をつけていること：自分をだまさない
過去のデータを見ながら AI を何度も直すと、その期間にだけ合わせ込んでしまい、成績が実力以上に良く見えます。旧システムはこれで回収率を大きく見誤りました。
そこで、

* **判定の方法と合格ラインを、結果を見る前に記録（事前登録）**し、
* **まだ誰も見ていない未来のレースで、1回だけ判定**します。
* 不合格になっても、同じデータで AI を直して再挑戦することはしません。

## これまでの結果

### 過去のレースでの成績（2019年〜2026年9月、約26,000レース）
今の有力候補（「候補2」）で、期待値1.3以上の単勝を100円ずつ買ったと仮定すると、

* 買った回数: 5,126回
* 回収率: **136.8%**（95%の確からしさで 117〜161% の範囲）
* 8年すべてで100%を超えた

**ただし、この数字は甘めです。**
* レースが終わった後の「確定オッズ」で買う馬を決めています。本番では、締め切り直前にオッズが動いた後の値は知ることができません。
* AI を作る途中で何度も見た期間の成績です。

さらに、的中率は約7%、当たったときの平均は約37倍の「穴馬狙い」です。仮に実力があっても、1,000レース程度では運が悪いと赤字になりえます。

### これからの判定（前向き検証）
本番と同じ条件で確かめるため、**発走の30分前・10分前・3分前のオッズを自動で記録**しています（JRA 公式サイトから取得）。
判定では3分前のオッズを使い（取れなかったレースは10分前、それも無ければ30分前）、1,000レースたまったら次の2つを満たすかを見ます。

1. AI の勝率が、オッズだけの見積もりより確実に正確である
2. 実際の払戻で、回収率が100%を超える

合格しても、まずは1点100円で3か月ほど実戦し、数字が合うかを確かめてから賭け金を考えます。

候補は2つ登録しています（どちらも中身は凍結済みで、判定まで変えません）。

| | C[all]（2026-09-17 登録） | 候補2（2026-10-01 登録） |
|---|---|---|
| 買い方 | 期待値1.2以上の単勝 | 期待値1.3以上の単勝 |
| 対象のレース | オッズの記録を始めた日以降 | 2026-10-02 以降 |

## 使い方

### 準備
`pip install -r requirements.txt`。Python は `C:\Users\aassz\anaconda3\envs\keiba-ai\python.exe` を使い、このフォルダの直下で実行します。

### 自動で動いているもの（Windows のタスクスケジューラ）
| タスク名 | いつ | やること |
|---|---|---|
| `keiba-odds-snapshot` | 毎日 8:00 から30分おき | 開催日なら、発走30・10・3分前のオッズを `data/v2/odds_snapshots/` に保存 |
| `keiba-weekly-ingest` | 月曜 20:00 | 先週のレース結果などを取得 → データを検査して取り込み → テスト → 判定までの進み具合を集計（ログ `logs/weekly_YYYYMMDD.log`） |
| `keiba-exotic-odds` | 月〜木 10:00 | 過去の3連複・3連単のオッズを少しずつ取得（別の検証用） |

**開催日は PC の電源を切らないでください**（スリープは大丈夫です）。オッズが記録できず、判定に使えるレースが減ります。

### 開催日に買い目を見る
```bash
python -m predict --candidate cand2 --live --watch      # 開催日の間ずっと、発走15分前になったレースから順に買い目を出す
python -m predict --candidate cand2 --live --within 20  # 発走まで20分以内のレースだけ1回
```
* 出馬表とその時点のオッズを取り、期待値1.3以上の単勝を表示します（1回3〜4分）。結果は `result/live/` に保存されます。
* オッズは発走直前まで動くので、買う直前には期待値が変わっていることがあります。
* 枠順・天候・馬場・馬体重などがまだ発表されていないと警告が出ます。その場合の買い目は信頼度が下がります。
* **判定が終わるまでは、表示を見るだけにして実際には賭けません。**

### 判定のときにやること（1,000レースたまったら、候補ごとに1回だけ）
```bash
python -m predict --candidate c_all --judge
python -m predict --candidate cand2 --judge
```
途中経過は `python -m predict --candidate cand2` で見られます（毎週の自動処理でも集計されます）。

### 手で動かすとき
| やること | コマンド |
|---|---|
| レース結果などの取得 | `python -m scrape weekly` |
| データの取り込み・特徴量の作成 | `python -m prep.ingest` → `python -m prep.features` |
| テスト | `python -m pytest tests scrape/tests` |
| オッズの記録の動作確認 | `python -m scrape snapshot --now --out-dir <作業用フォルダ>`（本番のデータに混ざらない） |
| AI の学習 | `python -m train --candidate cand2`（候補を登録したときに1回だけ。登録後は作り直さない） |
| 改良の効果を過去のデータで測る | `python -m evaluate --tag <名前> ...`（2026-09-06 までのレースだけを使う） |

**注意**: `models/v2/`（学習済みの AI）は Git に入っていません。消すと同じものを作り直せないので、消さないでください。

## フォルダの中身

処理は「① データを集める → ② 整える → ③ 学習 → ④ 検証 → ⑤ 実践」の順に分かれています。

```text
keiba/
├── scrape/          ① データを集める（netkeiba・JRA 公式からレース結果・血統・オッズなどを取得）
├── prep/            ② 集めたデータを検査して整え、AI に渡す形（特徴量）にする
├── train.py         ③ AI の学習
├── evaluate.py      ④ 過去のレースでの検証
├── predict.py       ⑤ 開催日の買い目・判定
├── model/           AI の部品（候補の設定は model/candidates.py）
├── live/            開催日・毎週の自動処理（タスクスケジューラから呼ばれるスクリプト）
├── experiments/     結論が出た実験
├── tests/           テスト
├── docs/            設計・事前登録・全実験の記録（rebuild_plan.md）、論文の形の整理（paper_draft.md）
└── data/ models/ result/ logs/ old/   【Git 管理外】データ・学習済みの AI・出力・ログ・旧システム
```

## データの不具合と、その対策

このプロジェクトで一番時間をかけたのは、AI の改良よりも**「その数字は本当に正しいのか」の確認**でした。見つけて直した主なもの:

1. **払戻データの列ずれ** — 保存した払戻データの約9割で列の順番がずれていて、3連複の払戻のつもりで馬単の払戻を読んでいました。
   旧システムの「回収率176.8%」はこの不具合によるもので、撤回しました（正しくは約80%）。
2. **別のレースのページが混ざる** — netkeiba は存在しないレース番号を指定すると、同じ日の1レース目のページを返します。今は、ページの中身が指定したレースと違えば保存しません。
3. **レース情報の空欄** — 芝/ダート・距離・天気・馬場が空欄のレースを、別のページから補っています。
4. **ID の書き方の違い** — 年によって騎手・調教師の ID が `1170` と `01170` のように違ったので、そろえています。
5. **取り込みのたびの自動検査** — 重複・抜け・オッズと払戻の食い違いなどを検査し、問題があればデータを保存しません。
   また、「未来のレース結果が AI の入力に紛れ込んでいない」ことをテストで確かめています。

### 構成
```
[段階1] 基礎モデル（オッズを使わない LightGBM、1〜3着の順序で学習）→ 各馬の勝率
[段階2] log(勝率) = a·log(オッズ由来の勝率) + b·log(基礎モデルの勝率) + 残差 LightGBM
        期待値（勝率 × オッズ）が閾値以上の単勝を買う
```
* 評価の指標は、勝ち馬の対数尤度が「オッズのみ」のモデルよりどれだけ良いか（C − A）と、事前に決めた期待値の閾値での回収率。
* 特徴量は176列。学習・検証・本番で同じ関数（`prep/features.py`）を使う。

| 部分 | 技術 | 実装 |
|---|---|---|
| 基礎モデル | LightGBM にレース内ソフトマックス（条件付きロジット）のカスタム目的関数 | `model/softmax.py` |
| | Plackett-Luce（1〜3着の順序の尤度）。2・3着の効用を λ=0.75 で割り引く（Henery / Stern 型） | `model/plackett.py` |
| | 3シード平均、早期打ち切りに使った年で温度を合わせる | `model/pipeline.py` |
| オッズとの結合 | Benter の2段階（条件付きロジットで結合） | `model/pipeline.py` |
| | 残差ブースティング: 結合をオフセットに固定し、ずれだけを LightGBM で学習。オッズ由来の勝率と人気順も入れ、市場の値付けの偏りを非線形に直す | `model/pipeline.py`・`model/market.py` |
| | 残差の学習期間は2015年から。半減期730日の指数重み | `model/pipeline.py` |

### 前進検証（2019〜2026-09-06、26,468R、確定オッズ）
| 版 | C − A（1レースあたり） | 2026年 | 期待値ベースの単勝 |
|---|---|---|---|
| C[all] | +0.0132 [+0.0108, +0.0156] | −0.0007 | 1.2以上 14,604点・120.5% |
| 候補2 | +0.0186 [+0.0161, +0.0210] | +0.0060 | 1.3以上 5,126点・136.8% [117.1, 160.5] |

* 候補2は C[all] より8年すべてで良く、差は +0.0055 [+0.0044, +0.0066]。
* 合格の条件: C[all] は C − A の95%下限 > 0 かつ回収率 > 100%。候補2は97.5%下限 > 0 かつ回収率（実際の払戻）> 100%。
* 効いたのは学習と結合の技術（1〜3着の順序で学習・残差の学習期間を広げる・残差にオッズ列・種類の違う版の単純平均）。
* 効かなかったもの: 特徴量の追加（第5〜7弾）、CatBoost・MLP・Transformer、温度補正、残差のハイパーパラメータ探索（DART を含む）、
  四半期ごとの再学習、Shin の確率、スタッキング、特徴量の絞り込み、芝ダ別のモデル、敵対的検証による重み付け、ランダム部分空間、1〜5着で学習。

## 旧システム（v1）
3連複を当てにいくシステムでした。2026年のテスト期間で回収率は約78%、実戦93レース（2026/7/18〜9/6）でも72.8%で、AI の評価が人気とほぼ同じで市場に勝てていませんでした。
この反省から作り直したのが今のシステムです。コードは git タグ `v1-final`（`git checkout v1-final`）、モデル・過去の予想・結果は `old/` にあります。
